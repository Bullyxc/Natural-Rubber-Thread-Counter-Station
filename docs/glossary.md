# Thread Counter Station glossary

| Term | Meaning in this project |
| --- | --- |
| Station | The fixed camera, fixture, controlled lighting, computer, and display used for inspection. |
| ROI | Region of interest; the configured rectangle containing the elastic product. |
| Dynamic raft ROI | Two-stage horizontal region selection. First inspect the full camera frame at reduced resolution to locate the elastic raft and its left/right outer bounds, then create a detailed counting ROI around those bounds with a small safety margin. A fixed central-width ROI must not clip wide products; full-resolution heavy processing remains limited to the dynamically cropped region for Pi 5 efficiency. |
| Elastic strand | One physical small elastic line bonded side-by-side into the elastic raft. This is the unit the station must count. |
| Elastic raft | One product sample made from multiple equal-size elastic strands bonded side-by-side. |
| Raft alignment | The elastic raft is presented approximately vertically. The algorithm must estimate and compensate for orientation errors up to ±15° from image vertical before comparing pitch or fusing evidence across background zones. A larger tilt is rejected with `ALIGN PRODUCT` rather than forcing a count. |
| Groove | The visible internal separation between two adjacent elastic strands. A groove is evidence for strand boundaries, but is not itself the counted unit. |
| Outer boundary | The detected leftmost or rightmost edge of the complete elastic raft. |
| Strand count | Number of physical elastic strands in the raft. For example, a raft containing 20 strands must report `COUNT=20`, regardless of how many grooves or edge peaks were directly detected. |
| Nominal strand count | Strand quantity required by the product specification before damage. `dual_background_sample_02.jpg` has nominal count 40 but is a user-confirmed QC-failed sample whose leftmost or rightmost strands may have been torn away. Nominal count is not automatically the same as the number of strands still visible in the captured image. |
| Visible strand count | Number of physical strand intervals supported by image evidence after any tear or missing outer material. For `dual_background_sample_02.jpg`, the accepted visible result is `COUNT 37` while the nominal specification remains 40. |
| QC-defective reference | A labelled diagnostic image that demonstrates a product defect rather than a clean counting target. It must not be used to tune the detector to hallucinate the nominal product count; nominal specification, visible measurement and QC decision are separate outputs. |
| Count QC decision | Compare visible `COUNT` with the nominal strand count supplied by the selected product specification. Equality produces `QC PASS`; inequality produces `QC FAIL`. For the torn reference sample, display `COUNT 37`, `EXPECTED 40`, and `QC FAIL — MISSING/TORN EDGE`; never replace the visible count with the nominal value. |
| Boundary-to-count rule | Sort the completed boundary sequence from left to right as left outer boundary, zero or more internal grooves, and right outer boundary. Every interval between adjacent boundaries is exactly one physical strand, so `COUNT = number of completed boundaries - 1`. Draw exactly one bounding box and one centerline for each interval. |
| Strand centerline | Overlay line drawn through the visual centre of one counted elastic strand. One accepted strand contributes exactly one centerline. The line is continuous across the excluded background-seam band even though pixels in that band do not contribute measurement evidence. |
| Strand bounding box | Rectangle enclosing one counted elastic strand between its inferred left and right boundaries over the accepted vertical extent. It shows the operator exactly which physical strand contributed to `COUNT`. The box is continuous across the excluded background-seam band so the overlay presents each strand as one object. |
| Visible raft extent | Vertical span used for centerlines and strand boxes. When a physical top or bottom end of the raft is visible, the overlay stops at that detected end; when the raft continues beyond the image, the overlay is clipped at the corresponding ROI boundary. Boxes are not forced to fill the complete ROI when a real product end is visible. |
| Grayscale candidate | Phase-one intensity representation used to score edges and grooves. RGB, HSV and LAB channel searches are explicitly out of scope until grayscale has been evaluated with real images. |
| Background seam | Automatically detected horizontal transition between the white upper background and black lower background. Its position is measured from each frame rather than assumed to be at 50% of the ROI height. |
| Seam exclusion band | Adaptive safety band above and below the detected background seam that is removed before strand analysis so the strong background transition cannot become a false elastic edge or groove. Its width is derived from the measured transition thickness and an automatic safety margin on each frame; it is not a fixed pixel or ROI-percentage value. |
| White-background zone | Usable ROI area above the seam exclusion band, evaluated independently in grayscale. |
| Black-background zone | Usable ROI area below the seam exclusion band, evaluated independently in grayscale. |
| Trusted zone | White- or black-background zone whose seam separation and strand evidence pass the agreed quality checks. An untrusted zone is excluded independently; failure of one zone does not invalidate the other zone or automatically discard the complete frame. |
| Zone measurement | One count and its geometric/quality evidence produced by one trusted background zone in one frame. A frame can therefore contribute zero, one or two zone measurements. |
| Cross-zone evidence fusion | Construction of one frame result using the strongest compatible evidence from both background zones. The left/right outer boundaries may come from one zone while groove positions and pitch come from the other zone in the same frame. |
| Zone evidence weight | Quality weight derived from edge clarity and pitch regularity for selecting or fusing white- and black-zone evidence inside one frame. It does not allow geometry to be borrowed from another frame. |
| Compensating quality score | Zone-quality rule in which exceptionally strong outer-edge evidence may compensate for weaker groove/pitch evidence, and exceptionally regular groove/pitch evidence may compensate for weaker outer edges. Outer-edge and pitch components are not independent hard gates; the outer-edge component may be zero when pitch evidence is sufficiently strong. |
| Periodic boundary completion | Recovery of weak or missing boundaries at integer multiples of the median strand pitch. At most two consecutive missing internal grooves may be inserted; three or more consecutive missing internal grooves make the frame fail. A weak left or right outer boundary may be extrapolated by no more than one median pitch per side from the nearest confirmed groove, and the predicted location must contain at least a weak image transition from the elastic raft to the background. If that supporting outline is absent, the frame fails rather than inventing an outer strand. |
| Groove-centre hypothesis | Phase-one method to test for converting a narrow physical groove's paired or clustered gradient peaks into one boundary at the groove centre. This is an experimental candidate, not yet a fixed production rule; it must be compared against direct profile-extremum and single-peak alternatives using labelled images from the final vertical, dual-background station. |
| Labelled reference image | A station image paired with explicit visible-count, nominal-count and expected-QC labels. Samples 01 and 03 are `40/40 PASS`; sample 02 is the torn-edge diagnostic `37/40 FAIL`, as recorded in `image/ground_truth.json`. |
| Phase-one count range | Temporary feasibility-test constraint of 30–50 physical strands (`40 ±10`). Candidate counts outside this range are rejected during the initial dual-background experiment. This range is not yet a permanent product specification. |
| Phase-one acceptance scope | The initial dual-background milestone covers grayscale strand detection, correct `COUNT`, one centerline and one bounding box per counted strand, and visible raft width in pixels. Colour classification, millimetre calibration and product-catalog identification are deferred until this milestone works on the labelled reference images. |
| Complete frame result | Self-contained measurement from one camera frame, including outer bounds, pitch, physical strand count, strand centerlines, strand bounding boxes and quality evidence. Cross-frame evidence fusion is forbidden. |
| Five-frame vote | All-or-nothing final `COUNT` decision. All five captured frames must independently produce a complete frame result; if any frame fails, the complete burst fails and no `COUNT` is displayed. When all five succeed, the candidate result is the median of their five strand counts. Zone-quality weights do not replace this median rule. |
| IQR outlier filter | Count-only Tukey filter applied after all five complete frame results exist. Compute Q1 and Q3 with `numpy.percentile(counts, [25, 75])` using NumPy's standard linear interpolation, set `IQR = Q3 - Q1`, retain counts within `Q1 - 1.5×IQR` through `Q3 + 1.5×IQR`, discard counts outside that range, then compute the final median from the retained counts. At least three of the original five frame counts must remain after filtering; otherwise the complete burst fails. |
| Ambiguous count | A four-value post-IQR result whose two central sorted counts differ. The station must not round their half-step median or invent an unobserved count; the burst fails with `AMBIGUOUS COUNT`. A four-value result is accepted only when its two central counts are equal. |
| Continuous inspection | Default live-station behaviour after startup. The system continuously captures, analyses and refreshes results without requiring `SPACE` or any other operator action. Failed bursts advance to subsequent frames automatically while retaining the failure reason for operator visibility. |
| Non-overlapping burst | Continuous frame grouping rule: analyse frames `1–5`, then `6–10`, then `11–15`, with no frame shared between bursts. The UI retains the latest accepted result while showing progress such as `MEASURING 3/5`; a failed burst displays its reason and the next five-frame burst starts automatically. |
| Scene-change burst reset | If placing, removing or replacing an elastic raft changes the image during a partially collected burst, discard every frame already collected for that burst. Wait until the scene is judged stationary, then immediately start a fresh five-frame burst so old, empty and new-sample frames are never mixed in one decision. |
| Stationary scene | A scene whose motion level inside the ROI remains below an automatically determined noise-aware threshold for three consecutive frames. Only after this condition is met may the station begin collecting a fresh five-frame measurement burst. |
| No-product state | State entered when no elastic raft is detected in the inspection ROI. Clear the previous `COUNT`, strand centerlines and strand bounding boxes immediately, then display `NO PRODUCT`; a result from a removed sample must never remain visible as though it belongs to the next sample. |
| New-product reset | A scene change caused by replacing or repositioning an elastic raft invalidates the previously accepted display even when no empty-background frame occurs between products. Immediately clear the old `COUNT` and overlays, show `MEASURING 0/5`, wait for the stationary-scene condition, then collect a fresh burst for the new scene. |
| One-second response target | Maximum desired latency from a stationary elastic raft being available for inspection to a stable displayed `COUNT`. The complete five-frame analysis and burst decision must fit within this one-second operator requirement on the final Pi 5 station. |
| Thread pitch | Approximate pixel distance between repeated thread peaks. |
| Per-product pitch | Strand size and therefore pixel pitch may differ substantially between product types or camera presentations, even when their physical strand counts are identical. Every complete frame must estimate pitch from that frame's raft; pitch learned from one sample or product must not be imposed on another. Within one raft, the strands are still expected to have a common nominal size and regular pitch. |
| Calibrated product pitch | Production product rules store `pitch_mm_min` and `pitch_mm_max`, computed from measured `pitch_px / pixels_per_mm`. Pixel pitch remains a diagnostic and temporary pre-calibration matching value only; it must not permanently bind a product rule to one processing resolution or lens setting. |
| Polarity | Whether the useful thread response is brighter (`white`) or darker (`black`) than its local surroundings. |
| Top-hat | Morphological operation that extracts bright local structure from a line-shaped neighbourhood. |
| Black-hat | Morphological operation that extracts dark local structure from a line-shaped neighbourhood. |
| Gradient axis | Intensity-gradient response along the configured counting axis; it emphasizes repeated thread boundaries. |
| Strip vote | A count made independently in several horizontal slices of the ROI; the median is the station count. |
| Agreement | Fraction of non-empty strips that produced the final median count. |
| Consensus position | A thread x-position shared by strips whose count agrees with the final result. |
| Width (px) | Detected product span between the left and right profile bounds in original ROI pixels. |
| `pixels_per_mm` | Calibration scale; pixels per millimetre in the product plane. |
| Width (mm) | `width_px / pixels_per_mm`; shown only after a positive scale is configured. |
| Lightness | Median CIE-L value from the LAB colour space in the measured span. Used for black/white classification. |
| Product rule | One ordered JSON entry matching colour, count, and optionally calibrated width to a product ID. |
| Automatic expected-count source | Runtime `EXPECTED` must come from the automatically matched product rule in `products.json`. The operator does not select a product and the program must not hard-code 40 or any other nominal count in Python. After a rule is matched, its nominal strand count is compared with visible `COUNT` to produce the count QC decision. |
| Defect-tolerant product match | Identify a product primarily from its configured strand-pitch or strand-size range, with colour and calibrated width as supporting evidence. Visible `COUNT` is deliberately not a mandatory product-match key: a torn 37-strand image must still match its nominal 40-strand product rule, then become `QC FAIL` rather than `NO_MATCH`. |
| Non-overlapping product pitch | Different product types do not use close or overlapping strand-pitch ranges. Pitch can therefore be the primary product identifier. The current largest, middle and smallest reference pitches are not an exhaustive catalogue; future product rules may define additional distinct pitch ranges anywhere between them. |
| Count-first output | A complete visible strand count is displayed regardless of whether `pitch_mm` matches any product rule. Product identification must never gate, suppress or alter visible `COUNT`. When no rule matches, show the measured count normally and treat product/expected/QC metadata as unavailable or `NO_MATCH`. |
| Count-first HUD | Full-screen hierarchy for the current phase: show visible `COUNT` as the largest text, show width/pitch/quality as secondary diagnostics, and show product/expected/QC only as a smaller status line. If no product matches, the small status reads `PRODUCT NO_MATCH` while the valid count remains prominent. |
| NO_MATCH | Safe result when no configured product rule matches the measurement. |
